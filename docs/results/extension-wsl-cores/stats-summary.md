# Extension 实验第二部分：WSL2 真实 Root-Domain 核数单变量对照（2 / 4 / 8 核）

采集时间 2026-11-25 13:50–14:28（UTC+8），全部在同一宿主机、同一容器镜像（`wcventure/period:stable`）与同一上游 PERIOD（`b6f72a7`）下完成。

## 实验动机与设置

在第一部分（[extension-cpu-affinity-merged/stats-summary.md](../extension-cpu-affinity-merged/stats-summary.md)）中，我们证实 `taskset` 构造的真子集掩码会违反 Linux `SCHED_DEADLINE` 的 root domain 准入约束（返回 `EPERM` 并引发 `SIGSEGV` 静默假阴性），因此不能用 `taskset` 回答“物理/逻辑核数本身是否影响 PERIOD 的错误检出率与波动”。

本实验改用 WSL2 `.wslconfig` 的 `processors=2 / 4 / 8` 真正改变 VM 级别的 root domain 核数，**不使用 `taskset`**，使每一档进程亲和性均覆盖完整 root domain（`0,1` / `0-3` / `0-7`），从而剥离 `EPERM` 干扰，独立观测核数对 `reorder_5_bad`（5 线程，225 调度）与 `reorder_10_bad`（10 线程，2350 调度）的影响。

| 项目 | 值 |
| --- | --- |
| 宿主机 | Intel i7-10510U（8 逻辑核），Docker Desktop / WSL2 kernel `6.18.58.1` |
| 容器与版本 | `wcventure/period:stable`（`8f47d8b9148f`），`--privileged`，上游 PERIOD `b6f72a7b06d01ffa7114b640312873ec2578a5ea` |
| 自变量 | `.wslconfig` `processors=2 / 4 / 8`（每次切换后 `wsl --shutdown` 重启，容器内实测 `nproc` 与 `default_affinity` 分别为 `2 (0,1)`、`4 (0-3)`、`8 (0-7)`） |
| 调度与轮次 | `-y -d 3`；`reorder_5_bad` 每档 5 轮、`reorder_10_bad` 每档 3 轮，共 **24 轮**（全部 `deadline_probe_rc=0`、收紧门禁 `gate_pass=1`、0 `sched_setattr` 错误、0 超时） |
| 采集脚本 | [scripts/extension_wsl_cores.sh](../../../scripts/extension_wsl_cores.sh) |

原始逐轮数据见 [rounds-summary.tsv](rounds-summary.tsv)（24 轮，含 `internal_time_s` 与 `external_wall_s`）。

## 与第一部分（`taskset` 真子集）的对照与核心结论

1. **彻底分离了“亲和性真子集失效”与“真实核数效应”两类机制**：
   - 在 8 核宿主机上用 `taskset -c 0-3`（4 核真子集）运行 `reorder_5_bad` 会触发 `EPERM → SIGSEGV`（耗时 240.29 s、0 错误）；而在 `.wslconfig processors=4` 构造的**真实 4 核完整 root domain（`0-3`）**下，`reorder_5_bad` 仅需 **18.39 s** 且 5/5 轮精确检出 **20** 次错误，`reorder_10_bad` 仅需 **93.60 s** 且检出 **89–90** 次错误，与 8 核基线（`16.58 s / 20` 与 `88.83 s / 90`）几乎完全一致。这以反事实对照直接证实：第一部分 4 核失效 100% 源自 `SCHED_DEADLINE` root domain 准入约束，而非 4 核算力不足。
2. **4 核与 8 核性能/检出率趋于饱和，2 核出现真实的超订退化（Over-Subscription Effect）**：
   - 当核数降至 **2 核**（完整 root domain，全部 8 轮 `SCHED_DEADLINE` 准入成功、无 `EPERM`/无 `EBUSY`、0 超时）时，两个基准均出现明显的检出率下降与方差放大：
     - `reorder_5_bad`（5 线程 > 2 核）：错误交错均值从 4/8 核的确定性 `20.00 ± 0.00` 降至 **`16.40 ± 2.79`**（范围 14–21，-18%），且 3/5 轮错失第 12 个调度上的首次命中（推迟至第 90–91 个调度）；
     - `reorder_10_bad`（10 线程 > 2 核）：错误交错均值从 4/8 核的 `89.67–90.00` 降至 **`79.33 ± 4.16`**（范围 76–84，-11.9%），2/3 轮首次命中从 27 推迟至 75–82；同时 dry-run `Runtime` 校准值从 4/8 核的 `1018–1428 ns` 膨胀至 `5180–12364 ns`，单轮耗时翻倍以上（`208.52 s` vs. `88.83–93.60 s`，慢 ~2.3×）。
   - 这直接回答了最初的扩展研究问题：**真实核数过少（2 核，线程数远超物理/逻辑核数）确实会削弱 PERIOD 在混合末周期的并发度与节拍精度，导致错误交错漏检、首次命中延后及波动增大；但核数达到 4 核后，对 5–10 线程基准已基本饱和，4 核与 8 核表现无显著差异。**
